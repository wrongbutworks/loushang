# SearchableList

`SearchableList` is a reusable focused widget for searchable long lists. It is
intended for settings-style pages, command-like selection lists, and other pages
that need a search input followed by a bounded result viewport.

It owns search/list focus movement, filtering, active item repair, visible
result windowing, optional settings-style chrome, and structured selection
results. Product pages still own item mutation, persistence, business actions,
and global page footer/status text.

## Inputs And State

- `SearchableListItem(key, label, value="", description="", disabled=False)`.
- `SearchableListSelect(key, label, value="")` returned on activation when no
  `on_select` callback is supplied.
- `query`: initial search query.
- `active_index`: initial active filtered item index.
- `focus_region`: `"search"` or `"list"`.
- `placeholder` and `empty_text`: text shown for empty search and no matches.
- `search_box`: renders a boxed search input.
- `detail_column`: aligns `value` or `description` as a second column.
- `column_headers`: optional `(label_header, detail_header)` row aligned with
  `detail_column`.
- `footer_hint`: optional widget-local hint row reserved after results.
- `theme`: optional `ThemeResolver`.

## Layout Behavior

Rendering order is:

1. search input, either one plain row or three boxed rows
2. optional column header row
3. result viewport
4. optional overflow row
5. optional footer hint row

When `footer_hint` is present and there are at least two rows available after
the search/header chrome, SearchableList reserves one row for it. Result rows
and overflow counts are then computed from the remaining viewport height.

`detail_column` applies the same label-column width to item rows and
`column_headers`. Detail text uses `item.value` first and falls back to
`item.description`.

Overflow text is generated by the widget:

- `↑ N more above`
- `↓ N more below`
- both joined when the visible window is in the middle of a long list

## Focus And Activation

When search is focused:

- text and paste edit the query
- `down` enters list focus when an enabled active item exists
- `enter` activates the active item
- `escape` clears a non-empty query
- unhandled `up` returns `None` so parent scaffolds or tab groups can move
  focus upward

When list is focused:

- `up` on the first enabled item returns focus to search
- `up` / `down` move between enabled items
- `pageUp` / `pageDown` move by the current visible result count
- `home` / `end` jump to first/last enabled item
- `enter` and `space` activate the active item

Disabled items remain visible but are skipped by navigation and cannot be
activated.

## Theme Tokens

| Token | Applies to |
| --- | --- |
| `widget.searchableList.search` | Non-empty search query text |
| `widget.searchableList.placeholder` | Empty search placeholder text |
| `widget.searchableList.box` | Box border around search input |
| `widget.searchableList.header` | Optional column header row |
| `widget.searchableList.item` | Normal enabled item rows |
| `widget.searchableList.focus` | Active item while list has focus |
| `widget.searchableList.disabled` | Disabled item rows |
| `widget.searchableList.description` | Value/description detail column |
| `widget.searchableList.empty` | No-results row |
| `widget.searchableList.overflow` | More-above/below row |
| `widget.searchableList.footer` | Optional footer hint row |

## Composition

`SearchableList` can live directly inside `TabGroup` content or inside
`PageScaffold` body content. Parent components should consume `None` returns
from search `up` when they want to move focus to tabs or page headers.

Use `footer_hint` for local SearchableList instructions. Use `PageScaffold` or
screen-level footer/status components for global state, status messages, and
cross-page commands.

## Test Obligations

Changes to SearchableList should cover:

- filtering by key and label
- active item repair after query or item replacement
- disabled item visibility and navigation skipping
- search/list focus transitions
- `enter` and `space` activation
- bounded viewport and overflow counts
- boxed search, column headers, detail alignment, and footer hints
- theme tokens preserving visible text
- composition playback with `TabGroup` or `PageScaffold`
